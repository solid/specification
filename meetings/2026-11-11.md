## Solid Memo - implementation feedback with Q/A
https://solid-memo.com/

* eP: Anton gave great presentation last week during Practitioners meeting
* AW: *Starting demo* Solid Memo is an application for learning through space repetition. 
* ...: starting without logging. There is a "meta" course on the appabout the app, possible to start with this.
* ...: start with some theory paragraph, then get questions.  Answer are written in your pod, as card in a "deck"
* ...: then, an algorithm for spaced repetition will schedule the next repetitions, and show later a card user needs to answer
* ...: a lot of pre-written course.. even one on Solid !
* ...: there is stats, number of corrects answers,  strike ( days in a row practicing .. ) , active time, a very good reward to look at when using the app
* eP: How do you count active time ? 
* AW: between prompt and answer time. but it is discarded if too long to answer ( > 3 min ) 
* Roberto: if in pod, how easy it is to interop ? for eg. with a teacher looking at its student stats
* ... [missed the answer]
* AW: dealing with a lot of security and ddos issue
* th: where are stored the course ?
* AW: one file per course, stored on the github. Possible to store a deck on the user Pod, but private to the user. To have a course on the app, need to make a PR. 
* eP: do you have agent skill to create course ?
* AW: no, agent should be able to easy make one form an exiting course
* eP: How does offline first work ?
* AW: stored in indexdb in the browser, if connect to Pod later, they are offered to move their data to their pod. 
* eP: how do you create identifier ? random uuid ?
* AW: not sure about that part, I can't answer the details. 
* [...]
* th: which authentication lib ?
* AW: inrupt browser loggin. also working on my own lib, but more as an exercise. 
* Roberto: What the testing regime ? 
* AW: I really like testing. I think unit tests are great. but not enough. So I also use e2e tests. Use real browser journey too, real confidence boost for refactoring.
* eP: useful links for user journeys: https://journey-mesh.openuji.org/#demo and https://ebremer.com/lws/ujg#state=app-start
* Roberto: read the [interoperability repport](https://github.com/solid-memo/website/blob/main/docs/interop.md). very interesting 
* eP: interested if you can document you testing flow
* eP: you use namespace of solidmemo.com , what do you think of the vocab ? would you use something with longer lifespan ( like w3c DNS )  ? Custom domain are risky for vocab if they get abandoned
* AW: I'm open to publish the vocab elsewhere. We need flashcard vocab, spaced repetition vocab, and I would like to reuse them. We don't need a solid-memo vocab. 
* eP: what if people want to change the vocab?
* AW: would happen on the github PR , create a discussion there. If working on more abstract spaced repetition vocab or flash card vocab, I don't need to be part of it, need to happen elsewhere. 
* eP: [...]
* AW: Semantic and interop grows organically, ppl does there thing on their side and then join forces.  Should not start we the spec and then implementation. Start from the bottom and then make a spec that work for all the use cases. 
* eP: some URI have a datetime in them. Are there many place where you put semantic in the url ? I use a general uuid and but all info in the metadata.
* AW: can work without the semantic in the url. But it help to do less request and improve performance. Otherwise the app would feel very sluggish. Look at the digest and resource history to see more on it. 
* AW: eTags are greates, allow me to not requests every time. server that don't implement eTags make solid-memo slower. 
* eP: Do you use notification ?
* AW: We don't have a server for that. I don't know how to to implement it. 
* eP: there is some way to integrate web hook and web push.
* AW: right now, no notification implementation
* eP: any last word?
* AW: Solid is very cool. Last question, what is LWS ?
* eP: Solid WG couldn't make it, and end up to be LWS WG. it is not backward compatible. I see it as a next iteration of Solid, but people might disagree with it. It should have future parity. 
* TallTed: LWS is a necessary ingredient to achieve the Solid project. Does cover all the Solid expectation which is more broad. LWS is not a Solid replacement, it is a necessary component to build it.
